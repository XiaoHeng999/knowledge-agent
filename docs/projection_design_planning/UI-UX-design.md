## 一、整体设计思路

### 1.1 核心设计哲学

AgentClaw 的 UI 围绕一个核心命题展开：**让"理解"的过程可视化、可操作、可追溯。**

- 不是信息流的堆砌，而是以 **领域（Domain）** 为第一公民的知识空间
- 不是单纯的聊天工具，而是 **研究 → 摘要 → 理解 → 决策** 的完整工作流
- 不是文件管理器，而是 **知识图谱** 驱动的上下文感知界面

### 1.2 设计原则

| 原则 | 含义 |
|------|------|
| 领域优先 | 一切交互以当前所在领域为上下文，侧边栏是核心导航锚点 |
| 渐进披露 | 信息按层级展开：概览 → 详情 → 原始数据，避免信息过载 |
| 本地优先感 | 不依赖网络状态，所有交互即时响应，后台同步静默进行 |
| 成本透明 | 模型调用成本始终可见，用户对每次 AI 操作有成本预期 |
| 安全覆盖 | 所有 AI 写操作可预览、可回滚，diff 可视化 |

**关键尺寸**：
- 侧边栏：固定 240px，可折叠至 48px（仅图标模式）
- 状态栏：固定 28px
- 标题栏：自定义 frameless，36px 高度
- 主内容区：填充剩余空间，最小宽度 640px

### 2.2 侧边栏结构

侧边栏分三个区域，从上到下：

| 区域 | 内容 | 交互 |
|------|------|------|
| 快捷入口 | 搜索框 + 收件箱（带未读计数） | 点击搜索弹出全局搜索；点击收件箱进入 Inbox 视图 |
| 领域导航 | 树形领域列表，支持父子层级 | 点击领域名 → 展开子菜单（知识/时间线/研究/专家）；点击子菜单 → 导航到对应视图 |
| 全局入口 | 研究总览、设置 | 固定在底部，始终可见 |

**领域树的交互细节**：
- 单击领域名 → 展开子菜单 + 高亮当前领域
- 双击领域名 → 进入领域概览页（Domain Overview）
- 右键领域名 → 上下文菜单（编辑配置、设默认模型、新建子领域、删除）
- 拖拽 → 调整领域顺序 / 设置父子关系

### 2.3 状态栏

状态栏是全局信息锚点，始终展示：

```
[模型图标] Claude Sonnet 4  |  今日消耗: $0.12  |  本月: $3.40  |  研究: 2/3 完成  |  🕐 09:30
```

- 点击模型名 → 弹出快速模型切换器（同对话内切换器的精简版）
- 点击成本数字 → 展开成本详情面板
- 点击研究状态 → 跳转研究仪表盘

- 最近决策（底部）：最新的 ADR 记录，强调"决策"而非"信息"

- 领域信息区始终显示，不随 Tab 切换变化

- 斜杠命令入口：输入 `/` 弹出命令选择器

- 点击事件 → 展开详情（来源、关联知识节点、AI 分析）
- 周期切换：月 / 季度 / 年
- 预测区域有"验证"按钮，用户可以在预测到期时标记准确/不准确

### 4.1 斜杠命令系统

### 4.2 模型切换

模型切换出现在三个位置：

| 位置 | 形式 | 作用范围 |
|------|------|---------|
| 状态栏 | 点击模型名 → 弹出快速切换器 | 切换全局默认模型 |
| 专家对话页 | 对话标题右侧下拉 | 仅影响当前对话 |
| 设置页 | 完整模型管理界面 | 持久化配置 |

**切换器设计**：
- 列出所有可用模型，按成本排序
- 显示当前选中模型（带圆点标记）
- 每个模型旁显示成本和 Provider
- 底部有成本优化提示

## 八、响应式策略

虽然 Electron 桌面应用窗口尺寸相对稳定，但仍需考虑：

| 场景 | 策略 |
|------|------|

## 十一、待讨论 / 待细化

1. **知识图谱可视化**：D3.js force-directed graph 是否足够？是否需要考虑 Cytoscape 或自绘 Canvas？
2. **Markdown 编辑器**：CodeMirror 6 vs Milkdown vs Tiptap？需要支持哪些扩展（LaTeX、图表）？
3. **快捷键体系**：需要定义完整的键盘快捷键映射表
4. **首屏加载优化**：知识图谱较大时的渲染策略（虚拟化？分层加载？）
5. **通知系统**：研究完成、导入完成等后台事件的通知方式（应用内 toast？系统通知？）
6. **拖放交互**：是否支持拖拽文件到窗口直接导入？拖拽知识节点建立关联？
7. **移动端伴侣**：是否需要？如果需要，是 Web 版还是原生 App？
