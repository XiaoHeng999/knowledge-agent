## 一、设计分析与决策

### 1.1 布局选型分析

经过对同类产品的调研分析：

| 产品 | 布局模式 | 核心特点 |
|------|---------|---------|
| Obsidian | 双侧边栏 + 可分割编辑区 | 左栏文件树，右栏反向链接/大纲，支持多标签分屏 |
| Notion | 左栏树形导航 + 块编辑器 | 上下文面板（评论/历史）以 overlay 滑入 |
| Roam Research | 双侧边栏 | 右栏作为「研究暂存区」，shift-click 并行阅读 |
| Cursor IDE | 编辑器 + 右侧 AI 聊天面板 | 面板可折叠、可拖拽调整宽度 |
| Claude Desktop | Tab 式统一布局 | 每个 Tab 重新配置面板布局 |
| ChatGPT Desktop | 对话 + Canvas 分屏 | 可拖拽调整的分屏 |

**结论**：AgentClaw 的功能多样性（对话、图谱、时间线、列表、设置）要求布局能根据当前场景 **自适应变形**。纯双栏或纯分屏都无法覆盖所有需求。

### 1.2 最终决策：自适应三面板布局（Adaptive Tri-Pane Layout）

采用 **左侧栏（固定导航）+ 主内容区（自适应）+ 右侧上下文面板（按需展开）** 的三面板架构。

| 需求场景 | 纯双栏的局限 | 三面板的优势 |
|---------|-------------|-------------|
| 专家对话 + 知识上下文 | 对话时看不到知识节点详情 | 右侧面板显示关联知识 |
| 知识图谱 + 节点详情 | 点击节点覆盖图谱或弹窗 | 右侧面板展示详情，图谱不丢失上下文 |
| 时间线 + 事件分析 | 展开事件打断时间线浏览 | 右侧面板展示分析，时间线保持滚动位置 |
| Diff 预览 | 模态弹窗打断工作流 | 右侧面板原地展示 diff |

## 二、整体布局结构

### 2.1 全局骨架

```
┌──────────────────────────────────────────────────────────────────┐
│  Title Bar [AgentClaw]     当前领域: AI/ML       [_][□][×]      │
├──────────┬───────────────────────────────┬───────────────────────┤
│          │                               │                       │
│  左侧栏   │      主内容区                  │  右侧上下文面板        │
│  (固定)   │      (自适应)                  │  (按需展开)            │
│          │                               │                       │
│  240px   │      flex-1                    │  0~320px              │
│  可折叠48px│                              │  可关闭                │
│          │                               │                       │
│  搜索     │  根据路由渲染:                  │  根据场景渲染:          │
│  收件箱(3)│  - Dashboard                  │  - 知识节点详情         │
│  ──────── │  - Domain Overview + Tabs     │  - 来源追踪            │
│  领域树    │  - Expert Chat               │  - Diff 预览           │
│  ▾ AI/ML │  - Knowledge Graph/List       │  - 关联知识             │
│    知识   │  - Timeline                   │  - 事件详情             │
│    时间线 │  - Research Dashboard         │  - 模型信息             │
│    研究   │  - Settings                   │                       │
│    专家   │                               │                       │
│  ▾ 前端   │                               │                       │
│  ──────── │                               │                       │
│  ⚙ 设置  │                               │                       │
├──────────┴───────────────────────────────┴───────────────────────┤
│ Status: Claude Sonnet 4 | 今日 $0.12 | 研究 2/3 | 🕐 09:30      │
└──────────────────────────────────────────────────────────────────┘
```

### 2.2 关键尺寸

| 区域 | 宽度 | 行为 |
|------|------|------|
| 左侧栏 | 240px（展开）/ 48px（图标模式） | 可折叠，窄窗口 (<900px) 自动折叠 |
| 主内容区 | flex-1，最小 640px | 填充剩余空间 |
| 右侧面板 | 0~320px | 按需 slide-in，可拖拽调整宽度 |
| 状态栏 | 100%，高 28px | 固定底部 |
| 标题栏 | 100%，高 36px | Electron frameless，自定义拖拽区 |

### 2.3 右侧面板的触发场景

| 触发动作 | 右侧面板内容 | 关闭条件 |
|---------|-------------|---------|
| 知识图谱中点击节点 | 节点详情（内容、来源、理解度、关联节点） | 点击关闭按钮 / 按 Esc / 点击空白区域 |
| 专家对话中 AI 引用知识 | 引用的知识节点详情 + 来源 | 对话继续 / 用户手动关闭 |
| 时间线中点击事件 | 事件详情 + AI 分析 + 关联知识节点 | 点击另一个事件 / 按 Esc |
| AI 建议修改时 | Diff 预览（红色删除 + 绿色新增） | 接受 / 拒绝修改后自动关闭 |
| 知识列表中悬停 + 点击 | 节点编辑器（原地编辑） | 保存 / 取消 |

- 每个 AI 回复旁有「追问」和「另起分支」按钮
- 参考: Discord 线程视图 + Git 分支可视化

**图谱交互**：
- 节点大小 = 理解度 (0-5)
- 节点颜色 = 类型 (concept/tech/person/event/decision)
- 连线粗细 = 关联强度
- 悬停节点：放大 1.2x + 发光效果，所有连接高亮
- 单击节点：右侧面板展开详情（不跳转页面）
- 双击节点：进入节点编辑视图（右侧面板变为编辑器）
- 滚轮缩放 + 拖拽平移
- 左下角 minimap 导航（参考 Obsidian 图谱视图）
- 支持按类型过滤

**时间线 UX 要点**：
- 实线圆点 = 已发生事件（来自研究和导入）

- 事件重要性用颜色标记：🔴 high / 🟡 medium / 🟢 low
- 点击事件 → 右侧面板展开详情（来源、关联知识节点、AI 分析）
- 周期切换：月 / 季度 / 年
- 预测区域有「验证」按钮

## 六、视觉效果与动效

### 6.1 右侧面板 slide-in 动画

```css
.context-panel {
  width: 0;
  transition: width 200ms cubic-bezier(0.4, 0, 0.2, 1);
  overflow: hidden;

.context-panel.open {
  width: 320px;
```

200ms ease-out 是 Obsidian 和 VS Code 验证过的最佳手感——快到感觉即时，慢到能看到方向。

### 6.2 Tab 切换动画

```css
.tab-content {
  animation: tabEnter 150ms ease-out;
}
@keyframes tabEnter {
  from { opacity: 0; transform: translateY(4px); }
  to { opacity: 1; transform: translateY(0); }
}
```

4px 的微位移比纯 fade 更有空间感。

## 十三、待讨论 / 待细化

1. **知识图谱可视化**：D3.js force-directed graph 是否足够？是否需要考虑 Cytoscape 或自绘 Canvas？
2. **Markdown 编辑器**：CodeMirror 6 vs Milkdown vs Tiptap？需要支持哪些扩展（LaTeX、图表）？
3. **快捷键体系**：需要定义完整的键盘快捷键映射表
4. **首屏加载优化**：知识图谱较大时的渲染策略（虚拟化？分层加载？）
5. **通知系统**：研究完成、导入完成等后台事件的通知方式（应用内 toast？系统通知？）
