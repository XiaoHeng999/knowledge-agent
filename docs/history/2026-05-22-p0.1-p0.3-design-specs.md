# P0.1-P0.3 Design Specification Completion

> Date: 2026-05-22
> Status: Completed

## Objective

Complete Phase 0 design specifications for P0.1 (Error Recovery), P0.2 (Testing Strategy), and P0.3 (Worker Architecture) — the first batch of pre-coding design tasks required before any application code is written.

## Implementation Summary

### P0.1 Error/Recovery Specifications (3 tasks)

**P0.1.1 — Error Registry for 12 Features**
- Created: `openspec/changes/agentclaw-implementation/specs/error-recovery/error-registry.md`
- Defined 43 error entries across all 12 features (F1-F12) plus a SYSTEM.UNKNOWN fallback
- Each entry includes: error code, severity level (critical/warning/info), user-facing message, recovery strategy, retry configuration, and log level
- Includes TypeScript interface definition for `ErrorEntry` and `ERROR_REGISTRY`

**P0.1.2 — TOP 5 Error Scenario UI Wireframes**
- Created: `openspec/changes/agentclaw-implementation/specs/error-recovery/top5-error-ui.md`
- Designed 5 error UI states with ASCII wireframes:
  1. API Failure Mid-Chat — retry banner with preserved draft
  2. Model Unavailable — disabled input with setup guidance
  3. Import Failure — error card with per-item retry
  4. Database Lock — non-blocking modal with auto-retry
  5. Graph Render Failure — automatic list view fallback
- Includes visual specifications (colors, typography, spacing) and detailed behavior flows

**P0.1.3 — Toast Component Specification**
- Created: `openspec/changes/agentclaw-implementation/specs/error-recovery/toast-component-spec.md`
- Defined 4 toast types (success/error/warning/info) with positioning, dimensions, colors
- Specified auto-dismiss rules (success 3s, error 5s), stacking behavior (max 3), entry/exit animations
- Includes accessibility spec (ARIA live region, keyboard support), React component interface
- Feature-to-toast usage map for all 12 features

### P0.2 Testing Strategy (3 tasks)

**P0.2.1 — Unit Test Strategy**
- Created: `openspec/changes/agentclaw-implementation/specs/testing/unit-test-strategy.md`
- Framework: Vitest + Testing Library
- Coverage targets: 75% overall, 80% services, 90% utils
- Mock strategy: Electron mocks, pi-mono interface mocks, real in-memory SQLite for DB tests
- Test categories: services, repositories, stores, components, utilities, error handling

**P0.2.2 — Integration Test Strategy**
- Created: `openspec/changes/agentclaw-implementation/specs/testing/integration-test-strategy.md`
- 3 integration layers: service layer, IPC bridge, database
- IPC test harness for simulating round-trip without real Electron
- ~75 integration tests estimated across all layers

**P0.2.3 — E2E Test Strategy**
- Created: `openspec/changes/agentclaw-implementation/specs/testing/e2e-test-strategy.md`
- Framework: Playwright with Electron support (replacing deprecated Spectron)
- 10 key user flows: onboarding, domain management, expert chat, knowledge management, import, research, settings/theme, version control, error scenarios, accessibility
- Isolation: temp data dir, mocked APIs, ~50-60 test cases

### P0.3 Worker Architecture Specifications (3 tasks)

**P0.3.1 — Electron Utility Process Architecture**
- Created: `openspec/changes/agentclaw-implementation/specs/worker-architecture/architecture.md`
- Single Utility Process with internal priority queue (HIGH/NORMAL/LOW)
- Communication via Electron MessagePort for streaming progress + IPC for commands
- 7 task types defined: embedding generation, batch embeddings, vector index build, graph layout compute, PDF text extract, RSS feed fetch, domain summary gen
- Error handling: task retry, worker restart with exponential backoff, graceful shutdown

**P0.3.2 — CPU/Memory Resource Budget**
- Created: `openspec/changes/agentclaw-implementation/specs/worker-architecture/resource-budget.md`
- Worker process limit: 256 MB memory, 100 max queued tasks
- Per-task budgets with scaling tables (memory, timeout, input limits)
- Memory monitoring with 90% warning threshold and 100% abort threshold
- Task-level memory pre-check before execution

**P0.3.3 — Worker Task Interface**
- Created: `openspec/changes/agentclaw-implementation/specs/worker-architecture/task-interface.md`
- `IWorkerTask<TPayload, TResult>` generic interface with state machine
- `ITaskHandler` interface with `execute`, `estimateMemory`, `cleanup`
- Progress reporting: rate-limited, task-type-specific messages
- Cancellation: `AbortController` pattern with cooperative checking
- 7 task-specific payload/result type definitions
