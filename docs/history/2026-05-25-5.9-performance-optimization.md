# 5.9 性能优化

> 目标：优化大图谱渲染、搜索性能、打包体积和首屏加载

## 实现摘要

### 5.9.1 大知识图谱虚拟化渲染
- **WebGL 批量渲染**：将逐节点创建/删除 buffer 改为一次性批量上传所有边和顶点数据，单次 `drawArrays` 调用绘制全部边/节点
- **视口剔除**：只渲染当前视口可见范围内的节点和边，大幅减少不可见元素的 GPU 计算量
- **鼠标滚轮缩放**：新增 `onWheel` 事件处理，实现滚轮缩放
- **requestAnimationFrame**：平移和缩放操作通过 rAF 调度，避免过度渲染
- **D3 数据连接优化**：ForceGraph 从 `selectAll('*').remove()` 全量重建改为 D3 enter/update/exit 增量更新模式
- **D3 子模块导入**：ForceGraph 从 `import * as d3 from 'd3'` 改为按需导入 `d3-selection`、`d3-zoom`、`d3-drag`、`d3-force`
- **图谱懒加载**：ForceGraph 和 WebGLGraph 改为 `React.lazy()` 动态导入，仅在切换到图谱视图时加载

### 5.9.2 搜索性能优化
- **搜索结果 LRU 缓存**：基于查询 + 域 + 过滤条件的 SHA-256 哈希缓存搜索结果（30 秒 TTL，100 条上限）
- **嵌入缓存**：基于文本内容 SHA-256 哈希缓存向量嵌入（5 分钟 TTL，500 条上限），避免重复计算
- **域节点 ID 缓存**：域节点 ID 集合 LRU 缓存（60 秒 TTL），避免每次搜索全表扫描
- **索引变更时缓存失效**：indexNode / removeFromIndex / reindexDomain 操作后清除搜索结果缓存

### 5.9.3 Electron 打包体积优化
- **ASAR 压缩**：启用 `asar: true`，将应用源码打包为单文件
- **原生模块解包**：`better-sqlite3` 等 `.node` 文件通过 `asarUnpack` 排除在 ASAR 外
- **文件排除**：排除 `*.ts`、`*.map`、测试文件、`docs/`、`openspec/`、`resources/` 等开发资源
- **LZMA 压缩**：Windows NSIS 安装器使用 LZMA 压缩
- **全局压缩**：`compression: xz` 减小产物体积
- **Next.js 优化配置**：配置 `splitChunks` 将 D3 和第三方库分离为独立 chunk，排除 Node.js 模块在客户端的 fallback

### 5.9.4 首屏加载优化
- **真实就绪检测**：LaunchLoader 从固定 2.8 秒延迟改为检测 Electron API 可用性（`app.ping()`），就绪后立即显示界面，最大等待 5 秒
- **重型组件懒加载**：OnboardingOverlay、CommandPalette、UpdateNotification 改为 `React.lazy` + `Suspense`
- **Suspense fallback**：懒加载组件使用 `fallback={null}` 不占位，图谱渲染器使用骨架屏 fallback
