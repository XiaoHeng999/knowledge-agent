# 5.3 错误处理统一 — 开发记录

> 日期：2026-05-25
> 阶段：Phase 5 打磨发布
> 任务：5.3 错误处理统一（5.3.1 – 5.3.5）

## 目标

建立统一的错误处理基础设施，覆盖渲染进程和主进程，包括：
- 全局错误边界，防止单个组件崩溃影响整个应用
- 统一的错误 UI 组件（错误横幅、Toast 集成）
- 错误恢复服务（指数退避重试、错误上报、降级策略）
- 结构化日志服务（JSON 格式、操作成本追踪）
- 调试模式（详细日志开关 + 性能指标面板）

## 实现摘要

### 5.3.1 全局错误边界

- **`src/components/error/error-boundary.tsx`** — React `ErrorBoundary` 类组件，捕获渲染异常，提供"重新加载区段"和"刷新页面"两种恢复路径
- **`src/app/error.tsx`** — Next.js 全局错误页面，处理未捕获的路由级错误
- **`src/app/(main)/layout.tsx`** — 在主布局中集成 `ErrorBoundary` 包裹主内容区，并挂载 `ToastProvider`
- **`electron/main.ts`** — 添加 `uncaughtException` 和 `unhandledRejection` 处理器，使用结构化日志记录

### 5.3.2 TOP 5 错误 UI

- **`src/components/error/error-banner.tsx`** — 通用错误横幅组件，支持 `error`/`warning`/`info` 三种变体，包含图标、消息、描述和操作按钮
- **`src/lib/error/error-registry.ts`** — 完整的错误注册表，覆盖 F1-F12 全部 43 个结构化错误定义，包含严重程度、恢复策略和重试配置

### 5.3.3 错误恢复服务

- **`src/lib/error/error-recovery.ts`** — 核心：
  - `retryWithBackoff()` — 指数退避重试函数，可配置最大次数、初始延迟、倍率
  - `useErrorStore` — Zustand 错误状态管理（上报、按功能查询、关闭）
  - `useLogStore` + `logger` — 渲染进程日志收集器（支持 debug 模式开关）
- **`src/lib/error/index.ts`** — 统一导出桶文件

### 5.3.4 结构化日志服务

- **`server/services/logger.ts`** — 主进程日志服务：
  - JSON 格式写入日志文件（`userData/logs/agentclaw-{date}.log`）
  - 四级日志（debug/info/warn/error）
  - `operation()` 方法支持操作计时和成本追踪（tokens、USD）
  - 在 `electron/main.ts` 中初始化和关闭

### 5.3.5 调试模式

- **`src/components/debug/debug-panel.tsx`** — 调试面板，三个 Tab：
  - **Logs** — 实时日志流（最近 100 条）
  - **Errors** — 活跃错误列表
  - **Metrics** — 平台信息和堆内存使用
- **`src/app/(main)/settings/page.tsx`** — 设置页新增"Developer"区段，提供 Verbose 开关和调试面板触发按钮
