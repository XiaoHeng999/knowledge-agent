# 1.2 IPC 通信层实现

> 日期：2026-05-23
> 阶段：Phase 1 — 基础架构
> 任务：1.2.1 ~ 1.2.4（Task #57 ~ #60）

## 目标

实现 Electron 主进程与 Next.js 渲染进程之间的类型安全 IPC 通信层，包括：
- 通道类型注册表（channel registry）
- Preload 桥接（contextBridge API）
- Handler 基类（错误处理、日志、超时）
- 通道注册入口

## 实现摘要

### 1.2.1 IPC 通道类型定义

**文件**：`src/lib/ipc/channels.ts`

- 定义 9 个域的通道名常量（`module:action` 命名规范）：app、db、model、domain、knowledge、inbox、research、settings、import
- 每个通道配备 Request / Response 类型接口
- `IpcChannelMap` 将所有通道名映射到 `{ request, response }` 类型对
- 提供 `ChannelName`、`ChannelRequest<C>`、`ChannelResponse<C>` 工具类型

### 1.2.2 IPC 桥接

**文件**：`electron/preload.ts`（重写）

- `contextBridge.exposeInMainWorld("api", api)` 暴露类型安全的 API
- API 按域分组（`window.api.app.*`、`window.api.knowledge.*` 等）
- 泛型 `invoke<C>` 函数确保请求/响应类型与通道注册表同步
- 保留 `on` / `removeListener` 用于主进程推送事件

**文件**：`src/types/electron.d.ts`（更新）

- `Window.api` 类型自动推导自 `ElectronAPI`

### 1.2.3 IPC Handler 基类

**文件**：`server/ipc/handler.ts`

- `registerHandler<C>(channel, handler, options?)` — 类型安全的 handler 注册
- 统一错误处理：`IpcError` 可序列化错误类 + 自动捕获未处理异常
- 请求日志：每次调用记录通道名和耗时
- 超时管理：`withTimeout()` 包装，默认 30 秒
- `unregisterAll()` 用于测试和优雅关闭

### 1.2.4 IPC Handler 注册

**文件**：`server/ipc/register.ts`

- `registerAllIpcHandlers()` 作为主进程唯一入口
- App / DB 域提供占位实现（后续任务替换为真实服务）
- 其余域预留空函数桩（Task 2.1.2 ~ 4.2.5 实现）

### 配置变更

- `electron/tsconfig.json`：`rootDir` 改为 `..`，`outDir` 改为 `../dist`，新增 `../server/**/*.ts` 和 `../src/lib/ipc/**/*.ts` 到 include
- `electron/main.ts`：导入路径从 `./ipc-register` 改为 `../server/ipc/register`
- 删除旧文件 `electron/ipc-register.ts`（功能已迁移）
