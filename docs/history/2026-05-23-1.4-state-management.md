# 1.4 状态管理基座 — 实施记录

**日期**: 2026-05-23
**任务**: Phase 1 — 1.4 状态管理基座
**状态**: 已完成

## 目标

为 AgentClaw 搭建 Zustand 状态管理层，包括持久化中间件、应用全局 store、领域 store，以及封装 IPC 调用的 React Hook。

## 实现摘要

### 1.4.1 Zustand Store 基类 (`src/stores/base.ts`)
- 实现混合存储适配器：IPC (`settings:get/set`) 为主，localStorage 为降级
- 通过 `createJSONStorage` 封装为 Zustand persist 中间件可用的存储
- 键名使用 `agentclaw:` 前缀，防止与其他 localStorage 数据冲突
- 待 1.5 SQLite 数据库层完成后，IPC 通道将自动对接 SQLite 持久化

### 1.4.2 应用全局 Store (`src/stores/app-store.ts`)
- 状态：`currentDomainId`、`currentView`（7 种视图）、`theme`（4 种风格）、`sidebarCollapsed`、`commandPaletteOpen`
- 使用 persist 中间件持久化核心状态（通过 `partialize` 过滤掉 `commandPaletteOpen` 等临时状态）
- 提供 setter 和 toggle action

### 1.4.3 领域 Store (`src/stores/domain-store.ts`)
- 状态：`domains` 列表、`currentDomainId`、`loading`、`error`
- 异步操作：`fetchDomains`、`createDomain`、`updateDomain`、`deleteDomain`，均通过 IPC 调用主进程
- 乐观更新：创建/更新/删除后立即更新本地列表
- 删除当前选中领域时自动清空 `currentDomainId`

### 1.4.4 IPC 状态同步 Hook (`src/lib/hooks/use-ipc.ts`)
- `useIpcQuery<T>(queryFn, deps)` — 只读 IPC 调用，挂载时自动请求，支持条件查询（传 `null` 跳过）
- `useIpcMutation<TArgs, TResult>(mutationFn)` — 写入 IPC 调用，手动触发，提供 `mutate`（吞错误）和 `mutateAsync`（抛错误）两种模式
- 两个 Hook 均返回 `{ data, loading, error }` 标准状态
