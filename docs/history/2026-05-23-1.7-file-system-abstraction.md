# 1.7 文件系统抽象层实现

## 目标

实现 Phase 1 中的文件系统抽象层（任务 92-95），为上层服务提供跨平台的文件操作接口。

## 实现摘要

### 新增文件

| 文件 | 职责 |
|------|------|
| `server/fs/paths.ts` | 跨平台路径工具，基于 `app.getPath('userData')` 解析数据目录、日志目录、领域目录等 |
| `server/fs/provider.ts` | `IFileSystemProvider` 接口 + `NodeFileSystemProvider` 实现，封装所有文件读写操作 |
| `server/fs/domain-dirs.ts` | 领域目录管理器，创建/验证/删除领域目录结构（config.yaml, skills/, tools/, prompts/, data/knowledge/, data/inbox/） |
| `server/fs/markdown-parser.ts` | 基于 gray-matter 的 Markdown 文件解析器，支持 YAML frontmatter 读写 |
| `server/fs/index.ts` | 模块汇总导出 |

### 设计决策

1. **IFileSystemProvider 接口**：抽象所有文件操作（readFile, writeFile, mkdir, stat, copy, move 等），支持在测试中替换为内存实现
2. **FsError 分类**：将 Node.js 错误码映射为 4 种语义错误（NOT_FOUND, ALREADY_EXISTS, PERMISSION, IO）
3. **单例模式**：通过 `getFileSystemProvider()` / `setFileSystemProvider()` 管理全局提供者实例
4. **路径缓存**：`paths.ts` 中缓存 `app.getPath('userData')` 结果，避免重复调用
5. **轻量 YAML 解析**：`domain-dirs.ts` 内嵌简易 YAML 序列化/反序列化，避免引入额外依赖

### 依赖

- 新增 `gray-matter` npm 包用于 Markdown frontmatter 解析
